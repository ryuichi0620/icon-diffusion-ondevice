# データセット方針（Stage 1）

## 狙い

**スタイルを 1 つに揃えた 50〜200 枚**。枚数より均一さが効く。バラつくと LoRA が
「アイコンらしさ」ではなく「いろんな絵柄の平均」を覚えてしまい、4 ステップでは特に濁る。

## トリガーワード

`configs/icon_lora.toml` の `trigger_word` で決める（初期値 `ICONST`）。

条件は 2 つ:

- **CLIP の語彙に無い綴りにする** — 既存の意味を引きずらないため。`ICONST` は BPE で
  複数トークンに割れるが、既知の単語ではないので実質的に新しい概念として学習される
- 一度決めたら Stage 2〜6 で変えない — 学習時と生成時で不一致だとスタイルが呼び出せない

生成時のプロンプトは `an icon in ICONST style, <被写体>, flat, minimal` の形に揃える。

## 揃えるべき軸

チェックリストとして使う。バラすなら「被写体」だけ。

| 軸 | 揃える | 例 |
| --- | --- | --- |
| 塗り | 揃える | フラット単色、グラデーション無し |
| 線 | 揃える | 輪郭線なし / 一定太さ |
| 配色 | 揃える | 2〜3 色のパレットに固定 |
| 背景 | 揃える | 単色 or 透過（後述） |
| 余白 | 揃える | 被写体を中央、周囲に一定マージン |
| 視点 | 揃える | 正面・平行投影 |
| 被写体 | **バラす** | カップ、鍵、カレンダー、… |

被写体だけをバラすことで「このスタイルで任意の物を描く」を学習させる。

## 前処理（`01_prepare_dataset.py` がやること）

1. **RGB 化** — 透過 PNG は指定色（既定は白）で合成する。α をそのまま落とすと
   境界に黒い縁が出るので、正しくアルファ合成する
2. **正方形化** — アスペクト比が 1:1 でない画像は中央クロップではなく**パディング**で正方形にする。
   アイコンは端まで意味があることが多く、クロップだと欠ける
3. **512×512 にリサイズ** — `LANCZOS`
4. **キャプション生成** — `metadata.jsonl` に 1 行 1 枚で書き出す
5. **健全性レポート** — 平均色・彩度・ユニーク色数のばらつきを出す。
   スタイルが揃っていないと分散が大きく出るので、学習前に気づける

出力:

```
training/data/processed/
  images/0001.png ... 
  metadata.jsonl        {"file_name": "images/0001.png", "text": "an icon in ICONST style, ..."}
  report.json           前処理の統計
```

## キャプションの付け方

DreamBooth-LoRA は `--instance_prompt` 一本でも回るが、被写体名を入れたほうがスタイルと
被写体が分離しやすい。`01_prepare_dataset.py` は次の優先順で被写体名を決める:

1. `--captions captions.csv`（`file_name,subject` の 2 列）があればそれ
2. 無ければファイル名から推測（`coffee-cup-01.png` → `coffee cup`）
3. それも無ければ被写体名なしの共通プロンプト

手で 100 行書くのが一番確実だが、ファイル名を生成時に付けておけば自動で済む。

## 権利まわり

- **市販アイコンセット（Noun Project、Flaticon 等）をそのまま学習に使わない。**
  多くのライセンスが再配布・派生物の作成を制限しており、学習データとしての利用は
  グレーどころか明示的に禁止されていることがある
- **クラウド生成で自前調達する**のが本プロジェクトの方針。生成に使うサービスの利用規約で
  「出力を学習に使ってよいか」を確認しておくこと（サービスによって明確に違う）
- 生成に使ったサービス名・日付・プロンプトを `training/data/SOURCE.md` に残す。
  後から出所を説明できる状態にしておく（このファイルは Git 追跡対象にしてよい）
- 既存の実在ブランドのロゴを模した出力は、学習データにも生成結果にも混ぜない

### このプロジェクトでの判断（2026-08-30）

OpenAI の利用規約には「Use Output to develop models that compete with OpenAI.」という
禁止事項がある。SD1.5 のスタイル LoRA がこれに当たるかは解釈次第で白とも黒とも読める。

**プロジェクトオーナーの判断は「A: 個人利用の範囲として現状維持」**。gpt-image-2 の
出力を学習データとして使い続ける。**配布・商用化を検討する段になったらこの判断を
見直すこと**（選択肢は専門家への確認、または CC0 素材からのデータ再構築）。
経緯と原文の裏づけは `training/data/SOURCE.md`。

## 枚数の目安

| 枚数 | 期待 |
| --- | --- |
| 〜30 | スタイルが安定しない。試運転向け |
| 50〜100 | 実用的な下限。まずここを目指す |
| 100〜200 | 企画メモの推奨レンジ |
| 200〜 | 均一さを保てるなら有効だが、揃えるコストが上がる |

### 実際にたどった枚数（2026-09-06 時点）

64 → 154 → 373 被写体 → **373 被写体 × 2 枚 = 746 枚**。効いたのは 2 箇所だけ。

- **64 → 154**: 歩留まり +10 ポイント、かつ **seed 間の分散が 27 → 10 ポイントに縮小**。
  枚数が足りないとスタイルの学習が平均化されない
- **1 被写体 1 枚 → 2 枚**: 構造エラー（持ち手が 2 つ・蓋が二重）が明確に減った。
  **物の構造は「同じ物体の複数例」からしか学べない。** 1 枚では持ち手の数を一度しか
  見せられない。被写体を増やすのとは別の効き方をする

一方 **「弱い被写体の近傍だけ足す」は全体を下げた**（docs/experiments.md Trial 5）。
その被写体は上がるが、狭い視覚族に偏るとスタイル信号が薄まる。

### `max_train_steps` は枚数に比例させない

<!-- ここを間違えて背景が壊れた。二度と踏まないこと -->

**一定 LR では「エポック数」ではなく「絶対ステップ数」が背景の崩れを支配する。**
データを 154 → 373 に増やしたときエポック数を保とうとして 1900 ステップにしたら、
背景の一様性が 70.8% → 21.9% に崩壊した。800 に戻すと 74.5% に回復した
（docs/experiments.md Trial 10）。

**枚数を増やしても 800 ステップのまま据え置くこと。**

### 生成プロンプトは固定する

Stage 0（`scripts/00_generate_raw.py`）の `PROMPT` は `training/data/SOURCE.md` に
記録した原文と一字一句同じにしてある。**ここを変えると既存データと分布がずれる。**
被写体だけを差し替えること。
